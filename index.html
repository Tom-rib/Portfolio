Projets d'infrastructure montés en labo, du besoin jusqu'à la documentation. Chaque carte indique ce que j'ai réellement mis en place et avec quoi.

conformite-nis2

terminé

Mise en conformité à la directive NIS2 (UE 2022/2555) pour une régie des eaux de 450 000 habitants qualifiée « entité essentielle » : du cadrage réglementaire jusqu'à la segmentation réseau et la gestion de crise.

  • Note de qualification réglementaire, analyse d'écart et feuille de route
  • Architecture segmentée IT/OT : zones, DMZ, VLAN, pare-feu et VPN
  • Chronologie de crise et notifications rédigées à 24 h, 72 h et 1 mois
  • Scripts de configuration VLAN, règles de pare-feu, vérification et sauvegarde
  • Schémas d'architecture avant/cible en sources Mermaid, livrable Word et soutenance
  • NIS2
  • Gouvernance
  • Segmentation IT/OT
  • VLAN
  • Pare-feu
  • VPN
  • Mermaid

terraform-lab-cyber

terminé

Infrastructure as Code appliquée à un laboratoire de cybersécurité : un seul terraform apply clone deux VM Debian 12 sous VMware Workstation, les configure par SSH, puis scanne la cible depuis la machine attaquante.

  • Pilotage de l'hyperviseur via l'API vmrest et le provider elsudano/vmworkstation
  • Code découpé et versionné : versions.tf, variables.tf avec validations, outputs.tf
  • Provisioners remote-exec : outillage nmap/masscan côté attaquant, service exposé côté cible
  • Contournement d'une limite du provider (adresse IP non implémentée) par data source external
  • Configuration complémentaire en Ansible, inventaire généré depuis le state
  • Aucun secret dans le dépôt : variables TF_VAR_* hors versionnement
  • Terraform
  • IaC
  • VMware Workstation
  • Debian 12
  • Ansible
  • PowerShell
  • nmap

ansible-hardening

terminé

Administration sans agent d'une flotte Linux hétérogène (Debian/Ubuntu et Rocky) depuis un serveur de contrôle unique, du durcissement jusqu'à la réponse à incident.

  • Durcissement SSH, comptes, pare-feu UFW, règles PAM
  • Centralisation des logs via Filebeat + templates Jinja2
  • Secrets chiffrés avec Ansible Vault
  • Scénario de réponse à incident et déploiement web sécurisé
  • Ansible

github-actions-ci-cd

terminé

Chaîne d'intégration et de déploiement continus sécurisée : chaque push sur la branche principale déclenche les vérifications, et seul un build vert déclenche le déploiement — sans qu'aucun secret ne transite par le dépôt.

  • Workflow GitHub Actions complet, découpé en 8 étapes du build au rollback
  • Application web minimale + script Bash de 5 contrôles d'intégrité bloquants
  • Déploiement idempotent par playbook Ansible sur Debian (Nginx + vhost validé)
  • Clés SSH en GitHub Secrets, chargées via ssh-agent sans écriture sur disque
  • inventory.ini généré à la volée en 600 puis détruit, contrôle MITM par known_hosts
  • Traçabilité : le SHA du commit déployé est inscrit dans la page servie
  • GitHub Actions
  • CI/CD
  • Bash
  • Ansible
  • Nginx
  • SSH
  • Debian
